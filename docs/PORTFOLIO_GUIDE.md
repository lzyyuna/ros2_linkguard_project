# 作品集与面试表达

## 30 秒项目介绍

“我做了一个网络感知型 ROS 2 机器人任务系统。系统用 Topic 承载连续控制和遥测，用 Service 注入网络场景，用 Parameter 做运行期策略配置，用 Action 管理可反馈、可取消的移动任务。我实现了时延、抖动和丢包模型，并把链路投递率接入安全策略，能够在通信恶化时停车和中止任务。后续我用 QoS 对照实验量化了通信配置对任务完成时间和控制新鲜度的影响。”

## 面试官可能追问

### 为什么网络场景切换不用 Topic？

它是低频、有明确成功/失败结果的一次性操作，Service 更合适。Topic 不保证请求者能获得直接响应。

### 为什么执行任务不用 Service？

任务持续数秒到数十秒，需要周期反馈、超时和取消。Service 不适合表达长任务生命周期。

### Parameter 和 Service 有什么边界？

Parameter 是节点配置，并带参数发现、查询和动态更新能力；Service 表达领域操作。单项阈值调节用 Parameter，原子地切换整套网络场景用 Service。

### 丢包后为什么机器人会安全停车？

robot_sim 有命令看门狗。超过指定时间收不到新指令，就将速度置零。这使安全性不依赖任务服务器能否及时发现故障。

### 当前模拟器有什么局限？

它是二维运动学模型，没有动力学、传感器噪声和真实无线信道；投递率是累计值，不能快速反映短时突发。D2 应增加滑动窗口指标、命令时间戳和 AoI。

## 不要这样表达

- “我会 ROS 2，因为我会发布订阅。”
- “用了 Action，所以项目很复杂。”
- “网络差时效果不好。”

要用职责边界、故障策略和量化指标表达工程能力。
